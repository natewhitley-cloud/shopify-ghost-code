# v1.3 — SEO Integrity Detection Spec

Three new FindingType values: `GHOST_CANONICAL`, `GHOST_TITLE`, `GHOST_OG`. All operate on the existing `read_themes` scope with no new permissions required.

Implementation follows the established per-file detector pattern: a module-scope regex, a `detect*` function that returns `CreateFindingInput[]`, and registration in `scanThemeFiles()` Pass 1. Each detector also needs a severity default in `severity-classifier.server.ts` and a new enum value in `prisma/schema.prisma`.

---

## 1. GHOST_CANONICAL

### What it detects

Orphaned `<link rel="canonical">` overrides left by SEO apps after uninstall. These typically appear as:

- Snippet includes that rendered a canonical tag but now output nothing (blank href)
- Hardcoded canonical URLs pointing to an app's proxy or a stale domain
- Liquid variables that no longer resolve (e.g., `{{ canonical_url_override }}`)
- Duplicate canonical tags in the same file (theme-native + app-injected)

### Detection heuristics

**Regex to extract canonical tags:**

```
/<link[^>]+rel\s*=\s*["']canonical["'][^>]*href\s*=\s*["']([^"']*)["'][^>]*>|<link[^>]+href\s*=\s*["']([^"']*)["'][^>]*rel\s*=\s*["']canonical["'][^>]*>/gi
```

Handles both attribute orderings (rel before href, href before rel). Same two-pattern approach as GHOST_HREFLANG.

**Trigger conditions (any of these fires a finding):**

1. **Empty or whitespace-only href** — `href=""` or `href="  "`. After app uninstall, a snippet that computed the canonical may render to empty string.
   - Regex: captured group matches `/^\s*$/`

2. **Unresolved Liquid variables in href** — `href="{{ seo_canonical }}"` or `href="{{ canonical_override }}"`. The theme engine outputs the raw tag literally or outputs an empty string.
   - Regex: `/\{\{[^}]*\}\}/` on the captured href value
   - Exclude known Shopify-native variables: `canonical_url`, `request.path`, `shop.url`, `page_url`, `url` (these are valid Liquid objects)
   - Pattern for exclusion: skip if href matches `/\{\{\s*(canonical_url|request\.path|shop\.url|page_url|url)\s*\}\}/`

3. **Duplicate canonical tags in the same file** — more than one `<link rel="canonical">` in a single layout or template file. The 2nd+ occurrence is flagged.
   - Collect all canonical tags per file; if count > 1, flag occurrences 2+ (same pattern as DUPLICATE_META detector)

4. **App-attributed canonical via code context** — canonical tag whose surrounding code snippet matches a known app via `identifyAppFromCode()`. This catches app-injected canonicals even when the href looks valid.

### False positive boundaries

- **DO NOT flag** the standard Shopify Dawn canonical pattern: `<link rel="canonical" href="{{ canonical_url }}">`. This is the native theme canonical.
- **DO NOT flag** canonical tags inside Liquid conditional blocks (`{% if %}`, `{% unless %}`, `{% elsif %}`). The LIQUID_CONDITIONAL_RE exclusion from GHOST_ROBOTS applies here — these represent intentional theme logic.
- **DO NOT flag** canonical tags inside `{% comment %}` blocks (handled by severity-classifier downgrade to LOW, same as all other detectors).
- **DO NOT flag** canonical tags whose href is a plain absolute URL with a valid-looking domain _unless_ there's a known app attribution match. A hardcoded canonical like `href="https://mystore.com/products/thing"` could be intentional.

### Severity

**HIGH**. Broken canonicals are the single most damaging on-page SEO problem. Google may index wrong URL variants, causing duplicate content penalties and traffic loss.

Add to `DEFAULT_SEVERITY` map: `[FindingType.GHOST_CANONICAL]: Severity.HIGH`

No additional nuance rules needed beyond the existing Liquid-comment downgrade.

### Known app patterns

These SEO apps are known to override canonical tags. Use `identifyAppFromCode()` on the surrounding snippet for attribution:

| App                  | Snippet names / code patterns                      |
| -------------------- | -------------------------------------------------- |
| Avada SEO Suite      | `avada-seo`, `avada-seo-suite`, `/avada-seo/`      |
| BOOSTER SEO          | `booster-seo`, `booster-apps-seo`, `/booster-seo/` |
| SEO Manager          | `seo-manager`, `/SEOManager/`, `/seo-manager/`     |
| Plug in SEO          | `plugin-seo`, `plug-in-seo`, `/pluginseo/`         |
| Searchie / SearchPie | `searchpie`, `searchpie-seo`, `/searchpie/`        |

No new `AppSignature` fields needed — existing `snippetNames` and `scriptPatterns` already cover these apps. The detector uses `identifyAppFromCode()` on the code snippet (same approach as GHOST_ROBOTS).

### Test cases

**Detections (should fire):**

1. Empty canonical href: `<link rel="canonical" href="">`
2. Whitespace-only href: `<link rel="canonical" href="   ">`
3. Unresolved Liquid variable: `<link rel="canonical" href="{{ seo_canonical_url }}">`
4. Unresolved complex Liquid: `<link rel="canonical" href="{{ canonical_override | default: '' }}">`
5. Duplicate canonicals in same file (2 tags, flag the 2nd)
6. App-attributed canonical (snippet contains `avada-seo` marker near the tag)
7. Reversed attribute order: `<link href="" rel="canonical">`

**False positive avoidance (should NOT fire):**

1. Native Shopify canonical: `<link rel="canonical" href="{{ canonical_url }}">`
2. Native with filter: `<link rel="canonical" href="{{ canonical_url | strip }}">`
3. Canonical inside Liquid conditional: `{% if template == 'product' %}<link rel="canonical" href="">{%endif%}`
4. Canonical inside Liquid comment block
5. Single valid hardcoded canonical: `<link rel="canonical" href="https://mystore.com/">`
6. Valid Liquid variables: `{{ request.path }}`, `{{ shop.url }}`, `{{ page_url }}`
7. File with no canonical tags at all (empty result)

## 2. GHOST_TITLE

### What it detects

Orphaned `<title>` tag overrides left by SEO apps after uninstall. SEO apps typically replace the theme's native `<title>` tag with custom Liquid logic that references app-specific metafields or variables. After uninstall, these render as blank titles or output raw Liquid variable names.

### Detection heuristics

**Regex to extract title tags:**

```
/<title[^>]*>([\s\S]*?)<\/title>/gi
```

Multiline capture between opening and closing title tags. Use the `lineNumberAtOffset` helper (already exists in scan-engine) since content may span lines.

**Trigger conditions (any of these fires a finding):**

1. **Empty or whitespace-only title content** — `<title></title>` or `<title>  </title>`.
   - Captured inner content matches `/^\s*$/`
   - BUT only flag in layout files (`layout/*.liquid`) where a missing title is truly broken. Template files may legitimately have no title tag.

2. **Unresolved Liquid variables in title** — Title contains `{{ variable }}` references that are not standard Shopify objects.
   - Extract all `{{ ... }}` expressions from the title content
   - Known safe Shopify variables (DO NOT flag): `page_title`, `shop.name`, `page_description`, `product.title`, `collection.title`, `article.title`, `blog.title`, `template`, any variable starting with `content_for_`
   - Flag if title contains `{{ ... }}` where the root variable is NOT in the safe list
   - Pattern for safe variables: `/\{\{\s*(page_title|shop\.name|page_description|product\.title|collection\.title|article\.title|blog\.title|template|content_for_\w+)/`

3. **App-attributed title override** — Title tag whose surrounding code snippet matches a known app via `identifyAppFromCode()`.

4. **Multiple title tags in same file** — More than one `<title>` tag in a single file. Flag the 2nd+ occurrence.

### False positive boundaries

- **DO NOT flag** the standard Dawn title pattern: `<title>{{ page_title }}{% if current_tags %} &ndash; tagged "{{ current_tags | join: ', ' }}"{% endif %}{% if current_page != 1 %} &ndash; Page {{ current_page }}{% endif %}{% unless page_title contains shop.name %} &ndash; {{ shop.name }}{% endunless %}</title>`. This is the native theme title. The key signal: if the title content includes `page_title`, it is almost certainly theme-native.
- **DO NOT flag** title tags inside Liquid conditional blocks. Same LIQUID_CONDITIONAL_RE exclusion.
- **DO NOT flag** title tags inside `{% comment %}` blocks.
- **DO NOT flag** empty titles in non-layout files (templates/, sections/, snippets/). Only layout files are expected to have a meaningful title tag.

### Severity

**HIGH**. Title tags are the single most important on-page SEO element. A blank or broken title causes Google to display the URL instead, tanking CTR from search results.

Add to `DEFAULT_SEVERITY` map: `[FindingType.GHOST_TITLE]: Severity.HIGH`

**Additional nuance rule:** If the title content contains `page_title` (Shopify's native variable) AND an unresolved app variable, downgrade to MEDIUM. The title will still render something useful from `page_title`; the app variable is additive damage, not catastrophic.

### Known app patterns

Same SEO apps as GHOST_CANONICAL, plus:

| App             | Additional title patterns                                           |
| --------------- | ------------------------------------------------------------------- |
| Avada SEO Suite | Injects `{{ avada_seo_title }}` or similar app-namespaced variables |
| BOOSTER SEO     | Renders title via `{% render 'booster-seo-title' %}`                |
| SEO Manager     | Uses `{{ seo_title }}` or `{% include 'seo-manager-title' %}`       |
| Plug in SEO     | Injects via snippet `{% render 'plug-in-seo-title' %}`              |

Attribution via `identifyAppFromCode()` on the code snippet.

### Test cases

**Detections (should fire):**

1. Empty title in layout: `<title></title>` in `layout/theme.liquid`
2. Whitespace-only title in layout: `<title>   </title>` in `layout/theme.liquid`
3. Unresolved variable: `<title>{{ seo_title_format }}</title>`
4. Unresolved variable mixed with valid: `<title>{{ page_title }} | {{ seo_suffix }}</title>` (flag but MEDIUM severity)
5. App-attributed title (snippet contains `booster-seo` near title tag)
6. Duplicate title tags in same layout file
7. Title containing only a broken render: `<title>{% render 'seo-manager-title' %}</title>` (detected via GHOST_SNIPPET, but also flag the title as suspicious if the snippet is known-app)

**False positive avoidance (should NOT fire):**

1. Native Dawn title: `<title>{{ page_title }} &ndash; {{ shop.name }}</title>`
2. Title with only safe variables: `<title>{{ page_title }}{% unless page_title contains shop.name %} - {{ shop.name }}{% endunless %}</title>`
3. Title inside a Liquid conditional
4. Title inside a Liquid comment
5. Empty title in a non-layout file (e.g., `templates/404.liquid`)
6. Title with `content_for_header` or other `content_for_*` variables
7. File with no title tags (empty result)

## 3. GHOST_OG

### What it detects

Orphaned Open Graph (`og:*`) and Twitter Card (`twitter:*`) meta tags injected by social/SEO apps via snippets. After uninstall, these output empty content values, reference undefined Liquid variables, or create duplicate/conflicting social meta tags.

### Detection heuristics

**Regex to extract OG and Twitter meta tags:**

```
/<meta\s+[^>]*(?:property\s*=\s*["'](og:[^"']+)["']|name\s*=\s*["'](twitter:[^"']+)["'])[^>]*>/gi
```

Captures `og:*` via property attribute and `twitter:*` via name attribute. Use a second regex to extract the content value from the same tag:

```
/content\s*=\s*["']([^"']*)["']/i
```

**Trigger conditions (any of these fires a finding):**

1. **Empty content attribute** — `content=""` or `content="  "` on an OG or Twitter meta tag.
   - Regex: content value matches `/^\s*$/`
   - Only flag for these high-value properties: `og:title`, `og:description`, `og:image`, `og:url`, `og:type`, `twitter:title`, `twitter:description`, `twitter:image`, `twitter:card`
   - Do NOT flag empty `og:locale`, `og:site_name`, or other low-impact properties

2. **Unresolved Liquid variables in content** — Content contains `{{ variable }}` that is not a standard Shopify object.
   - Same safe variable list as GHOST_TITLE plus: `product.featured_image`, `product.description`, `collection.image`, `collection.description`, `article.image`, `article.excerpt`, `page.title`, `page.content`
   - Additional OG-specific safe patterns: any variable accessed via `| img_url`, `| img_tag`, `| strip_html`, `| truncate` (these are Liquid filters applied to real objects)
   - Flag if content contains `{{ ... }}` where the root object is NOT in the safe list

3. **App-attributed OG tags** — OG/Twitter tag whose surrounding code snippet matches a known app via `identifyAppFromCode()`. This catches app-injected social tags even when content looks valid.

**Note on duplicates:** Duplicate OG/Twitter tags are already covered by the existing `DUPLICATE_META` detector (which catches any `<meta property="og:*">` or `<meta name="twitter:*">` duplication). GHOST_OG should NOT re-detect duplicates. It focuses exclusively on empty/broken content values and app attribution.

### False positive boundaries

- **DO NOT flag** native Shopify OG patterns. Dawn themes output OG tags using standard Liquid objects like `{{ page_title }}`, `{{ page_description | strip_html }}`, `{{ product.featured_image | img_url: '1200x630' }}`. If the content attribute uses only known-safe variables, skip it.
- **DO NOT flag** OG tags inside Liquid conditional blocks. Same LIQUID_CONDITIONAL_RE exclusion.
- **DO NOT flag** OG tags inside `{% comment %}` blocks.
- **DO NOT flag** low-impact OG properties with empty content: `og:locale`, `og:site_name`, `fb:app_id`, `twitter:site`, `twitter:creator`. These are non-critical.
- **DO NOT flag** tags that are already caught by DUPLICATE_META. Deduplicate: if the finding is a pure duplicate (same property, different content), DUPLICATE_META owns it. GHOST_OG only fires for empty/broken content or app attribution.

### Severity

**MEDIUM**. Broken OG tags degrade social sharing (wrong images, blank descriptions on Facebook/Twitter/LinkedIn) but do not directly harm search engine ranking. The impact is on social CTR, not organic visibility.

Add to `DEFAULT_SEVERITY` map: `[FindingType.GHOST_OG]: Severity.MEDIUM`

**Additional nuance rule:** Upgrade to HIGH if the property is `og:image` with empty content. A missing OG image is the most visible social sharing failure — Facebook/Twitter fall back to a random page element or show nothing.

### Known app patterns

| App             | OG/Social injection patterns                                                   |
| --------------- | ------------------------------------------------------------------------------ |
| Avada SEO Suite | Injects OG tags via `avada-seo` snippet; variables like `{{ avada_og_title }}` |
| BOOSTER SEO     | Renders social meta via `{% render 'booster-seo-og' %}` or similar             |
| SEO Manager     | Injects via `seo-manager` snippet                                              |
| Plug in SEO     | Social meta via `plug-in-seo` snippet                                          |
| Socialhead      | CDN: `cdn.socialhead.io`; snippet: `socialhead-og`                             |
| SEO King        | Snippet: `seo-king-meta`, `seo-king-og`                                        |

**New signatures to add to `APP_SIGNATURES`:**

```ts
{
  appName: "Socialhead",
  cdnDomains: ["cdn.socialhead.io"],
  scriptPatterns: [/socialhead\.io/, /SocialHead/],
  snippetNames: ["socialhead-og", "socialhead-social", "socialhead"],
  cssPatterns: [/socialhead/],
},
{
  appName: "SEO King",
  cdnDomains: [],
  scriptPatterns: [/seo-king/, /SEOKing/],
  snippetNames: ["seo-king-meta", "seo-king-og", "seo-king"],
  cssPatterns: [],
},
```

### Test cases

**Detections (should fire):**

1. Empty og:title: `<meta property="og:title" content="">`
2. Empty og:image: `<meta property="og:image" content="">` (HIGH severity upgrade)
3. Empty twitter:description: `<meta name="twitter:description" content="">`
4. Unresolved variable in content: `<meta property="og:title" content="{{ seo_og_title }}">`
5. Unresolved variable in og:image: `<meta property="og:image" content="{{ app_social_image }}">`
6. App-attributed OG tag (snippet contains `avada-seo` marker near the tag)
7. Whitespace-only content: `<meta property="og:description" content="   ">`

**False positive avoidance (should NOT fire):**

1. Native Dawn og:title: `<meta property="og:title" content="{{ page_title }}">`
2. Native og:image with filter: `<meta property="og:image" content="{{ product.featured_image | img_url: '1200x630' }}">`
3. Native twitter:card: `<meta name="twitter:card" content="summary_large_image">`
4. OG tag inside Liquid conditional
5. OG tag inside Liquid comment
6. Low-impact empty property: `<meta property="og:locale" content="">`
7. File with no OG tags (empty result)
8. Duplicate og:title (already handled by DUPLICATE_META — should not double-fire)
9. Static valid content: `<meta property="og:type" content="website">`

1. Add `GHOST_CANONICAL`, `GHOST_TITLE`, `GHOST_OG` to `FindingType` enum in `prisma/schema.prisma`

   - `GHOST_OG: MEDIUM`

6. Add nuance rule for GHOST_OG: upgrade to HIGH if property is `og:image` with empty content
