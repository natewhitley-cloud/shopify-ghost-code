# gc-tib slice 5: Clean copy UI (spec)

Status: building on `feat/gc-tib-clean-copy`, dark behind `CLEAN_COPY_ENABLED`. Service API: `app/services/clean-copy.server.ts` (`preflightCleanCopy`, `requestCleanCopy`, refusal types), models `app/models/fix-run.server.ts`, adapter `app/services/clean-copy-admin.server.ts`. Design source: `docs/spikes/2026-11-03-gc-tib-clean-copy-refresh.md` (D2 merchant publishes, D4 Professional only, D5 embed block + per-app confirm).

## 1. Pure view model: `app/lib/clean-copy-view.ts` (client-safe, no imports from .server)

Acceptance tests: `tests/lib/clean-copy-view.test.ts` (frozen, written first). Exports:

- `CleanCopyCandidate` `{ findingId, findingType, filename, lineNumber, appName: string|null, spanText: string|null, blocked: CandidateBlockReason|null }`. `spanText` is the exact code that will be removed, read live from the MAIN theme in the loader; null when blocked.
- `CANDIDATE_BLOCK_REASONS` = `APP_HAS_LIVE_EMBED`, `APP_UNKNOWN`, `NO_SPAN`, `IGNORED`, `PATH_NOT_ALLOWED`, `FILE_CHANGED` (live file no longer matches the scan). `candidateBlockCopy(reason)`.
- `groupCandidatesByApp(cands)`: groups sorted by app name, unknown app (null) last; inside a group sort by filename then line; split `selectable` / `blocked`. If any candidate of an app is `APP_HAS_LIVE_EMBED`, every candidate of that app is blocked with that reason.
- `RUN_REFUSAL_REASONS` (every `RunRefusal` of the service + `RUN_ACTIVE` + `DISPATCH_FAILED`), `runRefusalCopy(reason)` with a generic fallback for unknown codes.
- `fixItemReasonCopy(code | null)`: covers every FixItem reason the service writes (`FILE_CHANGED`, `CHECKSUM_UNVERIFIABLE`, `SPAN_MISMATCH`, `VALIDATION_FAILED:<splice reason>`, `UPSERT_FAILED`, `JOB_TIMEOUT`, `POST_WRITE_MISMATCH`, `NOT_FIXABLE_TYPE`, run-level reasons copied onto items such as `INCOMPLETE`), generic fallback, null = removed.
- `runSummary({ status, doNotPublish, failureReason, items: {status}[] })` -> `{ tone: "info"|"success"|"warning"|"critical", heading, body, showPreview, active }`. Rules in the tests: active statuses info; completed success with count; partial warning "X of Y"; failed critical with `runRefusalCopy(failureReason)`; `doNotPublish` always critical, no preview, says don't publish. Success copy says the live theme was not changed and the merchant publishes the copy themselves.
- `previewUrl(shopDomain, copyThemeGid)` -> `https://<shop>/?preview_theme_id=<numeric>`; null for missing/malformed id or a domain that is not a plain `*.myshopify.com` host. Reuse `themeIdToNumeric` from `app/lib/theme-editor-url.ts`.

Copy rules (guide/style-guide.md at ~/shopify/guide): short plain sentences, no em dashes, product name "GhostCode", the code is "leftover code", never "ghost code". Never show machine codes. Example tone: "Your clean copy is ready. We removed 13 pieces of leftover code from a copy of your theme. Your live theme was not changed. Preview the copy, then publish it from Online Store > Themes when you're happy with it."

## 2. Route `app/routes/app.scans.$scanId.clean-copy.tsx` (select + confirm)

- Loader: `authenticate.admin`; shop by session domain; if flag off or not Professional -> redirect to `/app/scans/:scanId`. Load the scan (must belong to the shop). Candidates = the scan's findings of the 4 fixable types (`FIXABLE_FINDING_TYPES`). Block reasons: no span -> `NO_SPAN`; path not allowed (`isAllowedFixPath`) -> `PATH_NOT_ALLOWED`; ignored (reuse the existing ignore matcher the scan page uses) -> `IGNORED`; app null -> `APP_UNKNOWN`; app in the scan's embed set (`parseLiveAppHooks(scan.liveAppHooks)?.embed`) -> `APP_HAS_LIVE_EMBED`. For the rest, read the affected MAIN files once via `createCleanCopyAdmin(admin).readFiles(mainThemeId, filenames)` (<= 50; beyond that show the first 50 files' candidates and a note) and set `spanText = content.slice(spanStart, spanEnd)` only when `md5(content)` equals the scan manifest md5 and `sha256(spanText) === spanSha256`; otherwise `FILE_CHANGED`. Return `groupCandidatesByApp(...)`, plus `hasWriteScope` (session scope includes `write_themes`), and run refusals from a cheap pre-check (stale scan) so the page can explain instead of offering a button that will fail.
- UI (Polaris web components `<s-*>`, mirror the scan page cards): intro text (what Clean copy does, in 3 short sentences: we make an unpublished copy of your live theme, remove only the code you select from the copy, you preview and publish it yourself; your live theme is never changed). One `<s-section>` per app: header with app name; a required checkbox "I've uninstalled {app}" (D5); each selectable candidate as a checkbox row (default UNCHECKED) with file, line and the `spanText` in a code block; blocked rows shown greyed with `candidateBlockCopy`. Submit button "Make a clean copy" disabled until at least one candidate is checked and every app with a checked candidate is confirmed. If `!hasWriteScope`: the button reads "Allow theme changes" and calls `shopify.scopes.request(["write_themes"])` (pattern: `app/lib/use-optional-scopes.ts`, guarded when the API is missing), then re-submits.
- Action: POST `findingIds[]`, `confirmedApps[]`; call `requestCleanCopy({ shopId, scanId, findingIds, confirmedApps, grantedScopes: session.scope split on ",", admin: createCleanCopyAdmin(admin) })`. ok -> redirect `/app/clean-copy/:runId`. `RUN_ACTIVE` -> redirect to the active run. Other refusals -> return `{ refusal, findings }` and render `runRefusalCopy` in a critical banner plus per-row `candidateBlockCopy`-style messages for refused findings. Validate form input (strings only, de-duplicated, bounded by `MAX_SELECTED_FINDINGS`).
- ErrorBoundary like the other app routes.

## 3. Route `app/routes/app.clean-copy.$runId.tsx` (status + result)

- Loader: auth; the run must belong to the shop (else 404); return run fields + items (filename, findingType, status, reasonCode) + `previewUrl` + code-editor link per changed file (`buildThemeEditorUrl` with the copy theme id) + theme library link (`https://admin.shopify.com/store/{handle}/themes`). Never return file content.
- UI: `<s-banner>` with `runSummary` tone/heading/body; while `active`, revalidate every 3 s (reuse `app/lib/use-scan-polling.ts` pattern), stop when not active. Buttons when `showPreview`: "Preview clean copy" (opens previewUrl in a new tab), "Open theme library". Results list: removed items ("Removed from {file}, line {n}") and not-removed items with `fixItemReasonCopy`. Footer note: "The copy stays in your theme library until you delete it. It counts toward your store's theme limit."

## 4. Entry point on the scan page (`app/routes/app.scans.$scanId.tsx`, minimal edit)

Loader adds `cleanCopy: { eligible: boolean, count: number }` = flag on AND Professional AND the scan has >= 1 finding of the 4 types with a span. Do the count query ONLY when the flag is on and the plan is Professional (existing frozen scan-page tests run with the flag off and mock only today's models, so no new call may run for them). Exception (gc-tib.20, audit r5 M1): the recent-runs read (`loadCleanCopyRunLines`, one indexed query, skipped while the scan runs) runs on every plan with the flag on or off, so a "don't publish" warning survives a downgrade, a rollback or removal from `CLEAN_COPY_SHOPS`. When eligible, render one secondary button "Make a clean copy ({count})" linking to `clean-copy` near the findings header. No other change to that file.

## 5. Tests (route tests mirror existing tests/routes patterns: mock `authenticate.admin`, db/models, the adapter)

Selection loader: redirect when flag off / not Pro / foreign scan; candidates + block reasons each; FILE_CHANGED when md5 or span hash differs; never returns file content beyond `spanText`. Action: ok redirect; RUN_ACTIVE redirect; refusal returned; malformed input (non-string, > MAX) rejected; confirmedApps passed through. Status loader: foreign run 404; previewUrl only via runSummary.showPreview rules; no content fields. Scan page: eligible false when flag off / Standard / no spans. Existing test files are frozen.
