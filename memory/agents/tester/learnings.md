# Learnings: tester

## Core

- Testing framework: Vitest v4 (not Jest). Config in `vitest.config.ts`. Runs cleanly alongside Vite v6.
- Tests mirror app/ structure in `tests/` directory (e.g., `tests/services/scan-engine.test.ts`).
- Mock Shopify admin with `createMockAdmin()` from `tests/mocks/shopify.ts`.
- Mock Prisma client with `createMockPrismaClient()` from `tests/mocks/prisma.ts`.
- Mock Inngest step tools with `createMockInngestStep()` from `tests/mocks/inngest.ts`.
- Use `npx vitest run <path>` for single-file runs without the npm script alias. (added: 2026-03-10, dispatch: .33)
- `mockReset()` before per-test `mockResolvedValueOnce` sequences. When `beforeEach` pre-populates a mock with `Once` calls, per-test overrides append rather than replace. Call `mockFn.mockReset()` first. (added: 2026-03-10, dispatch: S-01/S-02)
- When mocking ESM default exports (`import db from`), the vi.mock factory must use `{ default: { ... } }`. When writing helpers that accept nullable overrides, use ternary (`!== undefined ? value : default`) not `??` — nullish coalescing swallows `null`. (added: 2026-03-10, dispatch: S-04)
- Always use mockRejectedValueOnce (not mockRejectedValue) for error-propagation tests — permanent rejections bleed into sibling tests even with beforeEach clearAllMocks. (added: 2026-03-10, dispatch: .45)
- When mocking `app/shopify.server` for files that use dynamic `import()` (like Inngest functions), include ALL exports in the vi.mock() factory — not just the ones visible to the top-level module. Dynamic imports resolve through Vitest's mock registry. (added: 2026-03-10, dispatch: .62)
- vi.mock() hoisting in Vitest correctly intercepts dynamic imports (await import(...)). Mocked modules resolve from mock registry even inside step callbacks. (added: 2026-03-10, dispatch: .35)
- When adding tests for a new model function using a Prisma method not yet in the mock (e.g., findFirst on mockDb.finding), check the vi.hoisted mock object first and add the missing vi.fn() entry before writing assertions. (added: 2026-03-10, dispatch: acw-review)
- When a service function gains an optional parameter, tests using exact argument assertions break. Use `expect.anything()` for args the test doesn't care about to make tests resilient to signature additions. (added: 2026-03-28, dispatch: GC-monitoring-sprint)
- When a webhook handler gains a new import from a module already mocked, the mock factory must include the new export or Vitest throws at runtime. Grep for vi.mock of modified modules after any sprint dispatch. (added: 2026-03-28, dispatch: GC-monitoring-sprint)

## Task-Relevant

- billing.server.ts getPlanFeatures() is a pure function — ideal smoke test, no mocks needed. (added: 2026-03-10, dispatch: .33)
- When mocking `inngest/client` for functions using `inngest.createFunction()` at module load, include `createFunction: vi.fn((_config, _trigger, handler) => ({ fn: handler }))`. Without it, the source module throws at import time. (added: 2026-03-10, dispatch: S-01/S-02)
- Shopify's embedded admin has Cloudflare captcha — automated E2E (Playwright/Cypress) is impractical. Focus on unit + integration tests.
- Theme file content in test fixtures should use real Liquid syntax with known ghost code patterns.
- Prefer testing behavior (what the function returns) over implementation details (which internal method was called).
- Every service function should have both happy-path and error-path tests.
- Ask implementer for edge cases they considered but couldn't fully handle — those make the best test cases.
- Inngest function handlers accessible via scanTheme.fn — call directly as fn({ event, step }) to bypass SDK runtime. (added: 2026-03-10, dispatch: .35)
- For best-effort catch blocks, use mockResolvedValueOnce for preceding calls so only the targeted invocation rejects. mockRejectedValue without Once corrupts earlier steps. (added: 2026-03-10, dispatch: .35)
- formatDate uses toLocaleDateString('en-US') — ISO string inputs parsed as UTC midnight can shift by one day in negative-UTC-offset envs. Use Date object constructors with local-time args, or noon UTC times + regex matching. (added: 2026-03-10, dispatch: .49)
- For exhaustive enum coverage, pair individual named tests per value (readability + pinpoint failure) with a loop over all values that asserts set membership (forward-compatibility guard). (added: 2026-03-10, dispatch: .49)
- React Router's `redirect()` returns a Response object — it does NOT throw. Only Shopify SDK's `billing.request()` throws a Response. Test redirect by checking return value, not catch block. (added: 2026-03-10, dispatch: .62)
- Integration test structure: tests/integration/ directory for multi-step flow tests. Self-contained mocks per file. Focus on "does the chain work" not edge cases (those belong in unit tests). (added: 2026-03-10, dispatch: .62)
- When testing weighted scoring formulas, derive expected outputs by hand before writing expect() calls — comment the derivation inline. Prefer inputs that produce integer normalized deductions to avoid rounding surprises. (added: 2026-03-10, dispatch: 2oz-tests)
- (from reviewer) Any detector that uses a regex-pattern SPLIT (e.g. one pattern for `{% render %}` tag-form + another for bare `render` line-form) is a latent DOUBLE-COUNT risk. Always include a fixture containing BOTH forms (incl. a multi-line tag) in the same file and assert on the TOTAL finding count — not just "≥1 finding exists". (added: 2026-06-15, dispatch: GC-b34)
- (from reviewer) Golden-fixture tests for detectors should use VERBATIM upstream theme source (e.g. Shopify Dawn `snippets/meta-tags.liquid`) asserting zero false findings — a scanner's credibility rests on never flagging stock themes. This is the standard pattern for detector regression tests. (added: 2026-06-15, dispatch: GC-77m)
- (from debugger) To test a module-load boot guard (`if (NODE_ENV==='production' && !key) throw`), use `vi.stubEnv('NODE_ENV','production')` + `vi.resetModules()` + `await expect(import('../path')).rejects.toThrow(...)`; assert the dev case does NOT throw. Vitest defaults `NODE_ENV` to "test", so production-gated guards never fire in the suite — but always `vi.unstubAllEnvs()` in afterEach so stubs don't bleed into sibling tests. (added: 2026-06-15, dispatch: GC-be2)
- An async route action that `await`s a rejecting call with NO try/catch propagates the rejection as-is: `await action()` throws the original Error/Response unchanged (React Router does not wrap it at the action layer, so Shopify receives a 5xx). Assert with `await expect(action(args)).rejects.toThrow(...)` or `.rejects.toBe(responseObject)`. Shopify SDK's `authenticate.webhook` throws a Response on bad HMAC — assert `.rejects.toBe(response)` AND that the downstream effect (e.g. `deleteShopData`) was NEVER called. (added: 2026-06-15, dispatch: GC-s14)
- This repo's react-router `ActionFunctionArgs` requires `url`/`pattern` fields that `LoaderFunctionArgs` does NOT — when hand-building action args in a test, cast `as unknown as ActionFunctionArgs` (a plain `as ActionFunctionArgs` fails tsc even though the sibling loader-args pattern compiles, so the loader test is a false guide). (added: 2026-06-15, dispatch: GC-wex)
- To test an `InngestMiddleware` instance, invoke `await middleware.init()` → `.onFunctionRun({ fn, ctx })` to get the per-run hooks (`afterExecution` / `transformOutput`). Confirmed via `node_modules/inngest/components/InngestMiddleware.d.ts` (`init` is a readonly property on the instance). `onFunctionRun`'s TS return is a union (`{ afterExecution } | { transformOutput }`) that won't narrow at the call site — wrap the call in a helper with an explicit cast return type or tsc fails even when tests pass at runtime. Fakes: `fn = { name, id: () => "kebab-id" }`, `ctx = { event: { name }, runId }`, transformOutput ctx = `{ result: { error } }`. (added: 2026-06-15, dispatch: GC-f6w)
- REPO-WIDE pre-commit gotcha (flag for promotion to a rule): the pre-commit hook runs `eslint --max-warnings 0` with `import/order` — local relative imports must be path-sorted (e.g. `../../app/lib/*` before `../../inngest/*`) or the commit is REJECTED. Order imports accordingly up front to avoid a reorder-and-recommit cycle. Applies to all agents that write TS, not just tester. REFINEMENT (GC-kde): the eslint config sorts SIBLING (`./x`) BEFORE PARENT (`../x`) — this CONTRADICTS `.claude/rules/imports.md`, which says parent/sibling are one alphabetical group. Trust the linter, not the doc (doc needs a fix). Cost two commit bounces this session (import/order + a `prefer-const`). PROCESS FIX: subagents must run `npx eslint --max-warnings 0 <changed files>` before reporting done — `tsc --noEmit` + `prettier --write` do NOT catch import/order or prefer-const. (added: 2026-06-15, dispatch: GC-f6w; refined 2026-07-01 GC-kde)
- Month/week-boundary flakes: a relative comparison like `result.getUTCMonth() >= before.getUTCMonth()` (or a week-start check) silently fails at the Dec→Jan rollover (month 0 < month 11) when the test reads the real clock. Pin it: `vi.useFakeTimers()` + `vi.setSystemTime(new Date('2026-06-15T12:00:00.000Z'))` (noon-UTC to dodge the offset day-shift), assert EXACT month/year values not relative comparisons. NOTE: a mocked `getWeekStartUTC` (`vi.fn(() => new Date('2024-01-15T00:00:00Z'))`) is already deterministic — only tests that hit the REAL clock flake. (added: 2026-06-15, dispatch: GC-9x2)
- A top-level `afterEach(() => vi.useRealTimers())` is cheap insurance in any file using inline `vi.useFakeTimers()` — calling `useRealTimers()` when real timers are already active is a no-op, so it's safe to add unconditionally and stops fake-timer state bleeding into sibling tests. (added: 2026-06-15, dispatch: GC-9x2)
- `vitest.config.ts` coverage.include is now `app/**/*.{ts,tsx}` (was `.server.ts`-only) with `app/routes/**` no longer excluded — non-.server libs (`app/lib/*.ts`) and routes now report coverage. No thresholds configured, so broadening include can't fail CI. (added: 2026-07-01, dispatch: GC-zkv)

## Cross-Agent Notes
- (from implementer) `vi.resetAllMocks()` in `beforeEach` WIPES `mockReturnValue` implementations set inside a `vi.mock()` factory — a mock that needs a stable default (e.g. `isTrackerApp → false`) must be re-established in `beforeEach` after the reset, or use `vi.clearAllMocks()` (clears call history but keeps implementations) instead. (added: 2026-06-17, dispatch: GC-6vv)
- Testing TTL/time-based code deterministically: give the unit under test an INJECTABLE clock — `createTtlCache(ttlMs, now = () => Date.now())` — and in tests pass `() => nowMs` with a mutable `let nowMs`, advancing it by assignment. `vi.useFakeTimers()` does NOT work if the module captured a bare `Date.now` reference at import (the default must be a thunk `() => Date.now()`, not `Date.now`, to stay mockable). For code you can't refactor to inject, `vi.spyOn(Date, "now")` works since the cache reads `Date.now()` at call time — restore in afterEach. (added: 2026-07-01, dispatch: GC-kde)
